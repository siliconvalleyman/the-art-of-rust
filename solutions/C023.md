## Chapter 023

### EX-C023-01 — Expand an elided signature

```rust,edition2021
fn first_byte(text: &str) -> Option<&u8> {
    text.as_bytes().first()
}

fn first_explicit<'a>(text: &'a str) -> Option<&'a u8> {
    text.as_bytes().first()
}

assert_eq!(first_byte(""), None);
assert_eq!(first_byte("A"), Some(&b'A'));
assert_eq!(first_explicit("A"), first_byte("A"));
```

The only input reference supplies the output lifetime.
When `first()` succeeds, it borrows the first byte
of the input. Returning a fresh copy of the number
would give a different return type and ownership behavior.

### EX-C023-02 — Choose a source for a returned view

```rust,edition2021
fn second<'a>(_: &str, data: &'a str) -> &'a str {
    data
}

let stored = String::from("saved");
let view;
{
    let brief = String::from("temporary");
    view = second(&brief, &stored);
}
assert_eq!(view, "saved");
```

The explicit parameter relates the result only to
the second input. The first input is available for
the call and is released at the inner scope end.
Using a single named lifetime on both inputs would
tie result availability to the shorter caller region.

### EX-C023-03 — Require a common region

```rust,edition2021
fn select<'a>(left: &'a str, right: &'a str, use_left: bool) -> &'a str {
    if use_left { left } else { right }
}

let left = String::from("left");
let right = String::from("right");
assert_eq!(select(&left, &right, true), "left");
assert_eq!(select(&left, &right, false), "right");
```

The output is supported by both input types for the
selected `'a`. If the first and second input had
unrelated lifetimes, promising only the first one's
region would leave the second branch unable to fulfill
that promise. Running just the first branch does not
verify the interface for calls choosing the second.

### EX-C023-04 — Repair a return of local data

Change the result type to `String`. Return the owned
value without creating a reference to it. The
caller now holds the allocation and can later release
it by ending that owner's scope. Giving the
original invalid reference the annotation
`'static` cannot extend the local storage.
Credit requires the actual compile failure and
a passing assertion after the repair.

### EX-C023-05 — Distinguish a static bound by observation

`Rc` is a reference-counted owner. Its
`strong_count` operation reports how many owning
handles share the data. Chapter 57 derives its
ownership model.

```rust,edition2021
use std::rc::Rc;

fn consume<T: 'static>(value: T) {
    drop(value);
}

let original = Rc::new(17);
let another_owner = Rc::clone(&original);
assert_eq!(Rc::strong_count(&original), 2);
consume(another_owner);
assert_eq!(Rc::strong_count(&original), 1);
```

The shared ownership handle here contains owned data.
Creating the second handle gives two owners, and
consuming it releases one. The generic bound says
the type does not rely on short-lived borrows. The
body's explicit drop determines when this instance
is released. A static reference is a view and need
not own its referent or control its destruction.

### Interview answers for Chapter 023

**IQ-C023-01.** Both inputs must be valid for that
chosen region, and the returned view must also be
valid for it. The function can return either input
under that relationship. The original owner scopes
can differ as long as the required common region
is available.

**IQ-C023-02.** A String owns its buffer and contains
no borrow tied to the local variable's scope. A
reference to that string requires the local owner to
remain usable. Requiring a static reference would
promise access beyond what the local owner supports.
