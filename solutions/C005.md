## Chapter 005

### EX-C005-01 — Translate under permissions

```text
page = address divided by 16, rounded down
offset = remainder of address divided by 16
if page has no entry in the process map: return unmapped
if entry denies the operation: return permission error
return 16 times the entry's frame number plus offset
```

A read of `0x23` in A gives `0x93` and B gives
`0xc3`. A write in A gives `0x93` as well. A write in B
fails and `0x30` has quotient 3, which is unmapped in
either supplied map. The arithmetic reconstructs the same
offset within the permitted mapped frame. Using the same
table for both processes conflates the address spaces.
Award credit for performing the permission test before
returning a translated address.

### EX-C005-02 — Keep a scheduler trace

The intervals 0–1, 1–2, 2–3, and 3–4 run A, B, B, and A.
B completes at time 3 and A completes at time 4. With A
ready at time 4, the core is idle during 3–4 and A completes
at time 5. For a runnable thread, decrement its remaining CPU
steps only in an interval assigned to it. In the example
the read occupies A's first step, and waiting adds no CPU
steps. Charge an idle interval to neither thread. Award credit
for a table distinguishing readiness and time on the core.

### EX-C005-03 — Implement a parity recognizer

Start with a true `even` flag, then invert it for each 1.
Return the flag after the last input. Each transition preserves
that the flag is true exactly when the consumed prefix contains
an even count of 1s. Finite input accounts for termination.
The four test outputs are true, false, true, and false.
There is one transition per bit. Initializing to false reports
the opposite answer even for empty input. Award credit for
using one bit of state, omitting the input position from the
memory count when it is managed by the traversal.

### EX-C005-04 — Recognize bounded nesting

Initialize depth to 0. On `(`, fail if depth equals
`D`, otherwise increment it. On `)`, fail if depth
is zero, otherwise decrement it. At the end accept depth 0
or report unfinished. The invariant is that depth equals the
number of unmatched openings in the processed prefix and
lies in 0 through `D`. Each successful step preserves both
claims. The two immediate checks find the first invalid
prefix. On success all openings have a matching closing.
Empty input is accepted. At depth 1, `()()` succeeds,
`(()` fails at the second opening, `)(` fails at the
first closing, and `(` ends unfinished. Checking only the
net count can accept `)(`. The function takes at most one
transition per symbol and a counter with range 0 through
`D` plus fixed traversal state.

### EX-C005-05 — Distinguish an interpreter error

Set state to 0. For each byte, keep state on 0, replace it
by `1 − state` on 1, return it immediately on 2, and
return invalid-opcode error otherwise. End of the sequence
without a return produces missing-halt. The invariant is the
state equals the parity of opcode-1 occurrences in the
successfully interpreted prefix. The four results are 0,
1, missing-halt, and invalid opcode at index 1. The
contract ignores the byte 9 after halt. Rejecting all invalid
bytes in an up-front scan changes that behavior. Report
the distinction between program-format validation and the
specified interpretation rule.

### Interview answers for Chapter 005

**IQ-C005-01.** Loading can fail while trying to find a
required runtime library. The earlier compiler and linker
already produced a file. “It compiled, so it must run”
assumes runtime resources were available during compilation
and remains insufficient evidence that they are available
at startup.

**IQ-C005-02.** Observe scheduling delays, blocked time,
I/O completion, and whether the measurement includes startup
or cleanup. A thread waiting for a read may use little CPU
while taking substantial elapsed time. Blaming instruction
speed without evidence ignores time when the thread was
unrunnable or waiting its turn.
