## Chapter 002

### EX-C002-01 — Fill bits from least to most significant

```text
bits = eight zeros
quotient = input
for position from 7 down through 0:
    bits[position] = quotient remainder 2
    quotient = quotient divided by 2, rounded down
return bits
```

Array positions increase from the displayed left edge, so position
7 is the least significant display position. Each step removes
one low bit. The division invariant from the chapter shows the
array reconstructs the input once the quotient is zero. The code
always performs eight assignments. An ascending loop that puts
the first remainder at position 0 reverses the format. Use 37 to
catch that mistake, since 0 and 255 look the same in either order.

### EX-C002-02 — Decode a two-digit label

Read exactly two bytes. For an ASCII digit between `0` and `9`,
subtract the byte value of `0`. For `A` through `F`, subtract
`A` and add 10, and do the same with lowercase `a` through
`f`. If either byte is outside those ranges, return an error.
If `hi` and `lo` are the two values, return `16 × hi + lo`.
Its maximum is `16 × 15 + 15 = 255`. The input `aF` decodes
as `16 × 10 + 15 = 175`. The empty field and fullwidth
character fail the two-byte requirement. `0x` fails because
`x` is outside all three digit ranges. Whitespace fails either
length or digit validation. Award credit for deterministic failure
on malformed input and a value for `00`.

### EX-C002-03 — Keep the carry

**Executable Rust preview.** After the first Rust programming
chapter, read this implementation alongside the column proof.

```rust,edition2021
{{#include ../examples/foundations/src/representation.rs:add_byte}}
assert_eq!(add_byte(255, 1), (0, true));
assert_eq!(add_byte(255, 255), (254, true));
```

The low column of 255 plus 1 produces 0 and carry 1. The
remaining seven columns each add 1 and 0 with carry 1, so
the byte is 0 and the outgoing carry is still 1. Each column
total is at most 3. The prefix invariant in the chapter proves
that the low result and outgoing carry reconstruct the ordinary
sum. The separate Rust test compares all byte pairs with a
widened reference. Replacing the carry by a check that the
answer is zero would miss 255 plus 255 and misclassify 0 plus 0.

### EX-C002-04 — Decode two bytes in a declared order

Reject any input whose length is different from two. Label the
bytes `first` and `second`. For big-endian input, return
`256 × first + second`. For little-endian input, return
`first + 256 × second`. The maximum in either case is
`256 × 255 + 255 = 65535`. Widen the high byte before the
multiplication. Using the same byte twice can let a reversal
pass. The two distinct bytes in the problem yield 4660 and 13330.

### EX-C002-05 — Choose a count overflow contract

Call the addition with carry, then return an error if the carry
is 1 and the byte otherwise. The postcondition is that a result
exists exactly when the ordinary sum is representable. For 250
plus 5, the low result is 255 and the carry is clear. For 250
plus 6, the low result is 0 with carry set. The latter shares its
wrapped byte with 0 plus 0. The operands can support a different
overflow check, but the wrapped result by itself cannot distinguish
the situations. Award credit for preserving both kinds of outcomes.

### Interview answers for Chapter 002

**IQ-C002-01.** `A6` uses one hex character for the high nibble
and one for the low nibble. The byte being displayed has value 166.
As text, the two characters have distinct encodings. Writing “hex
takes two bytes” misses which level is being measured.

**IQ-C002-02.** Both operations can use the same wrong order for
the specified format. A round trip tests their agreement. An
external specimen with documented bytes and a known asymmetric
value tests agreement with the format. Repeating the round trip
on more values cannot distinguish the two internally consistent
orders on that host.
