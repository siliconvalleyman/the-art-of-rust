## Chapter 048

### EX-C048-01 — Choose exact membership or a value

```rust,edition2021
use std::collections::{HashMap, HashSet};
let mut pending = HashSet::new();
assert!(pending.insert("app"));
assert!(!pending.insert("app"));
let mut approved = HashMap::new();
assert_eq!(approved.insert("app", 10), None);
assert_eq!(approved.insert("app", 11), Some(10));
assert_eq!(approved.get("app"), Some(&11));
```

The set records presence once. The map returns the old version and
stores the new one for later lookup.

### EX-C048-02 — Apply the hash contract

Hash the account ID because it determines equality. Labels may vary
within an equivalence class, so including them directly could give
equal records different hashes. Different IDs can share a hash. The
table resolves that case by comparing keys for equality.

### EX-C048-03 — Count a fixed-occupancy query

With replacement there are `8 * 8 = 64` equally likely ordered
pairs, of which `3 * 3 = 9` pass. The probability is `9/64`.
Without replacement there are `8 * 7` pairs and `3 * 2` pass,
giving `6/56 = 3/28`. A repeated position is allowed only in the
first experiment.

### EX-C048-04 — Show one false positive and one rejection

```rust,edition2021
{{#include ../data-structures/src/membership.rs}}

let mut filter = Bloom64::default();
filter.insert([10, 14]);
filter.insert([9, 12]);
assert!(filter.might_contain([10, 14]));
assert!(filter.might_contain([9, 12]));
assert!(filter.might_contain([10, 12]));
assert!(!filter.might_contain([10, 11]));
```

The two insertions jointly set the positions for `[10, 12]`.
Position 11 remains clear. The check for a pair containing it
fails regardless of the other position.

### EX-C048-05 — Review an LRU policy

```rust,edition2021
{{#include ../data-structures/src/lru.rs}}

let mut cache = SmallLru::new(2);
assert_eq!(cache.insert("A", 10), Insertion::Stored);
assert_eq!(cache.insert("B", 20), Insertion::Stored);
assert_eq!(cache.insert("A", 11), Insertion::Updated(10));
assert_eq!(cache.get(&"unknown"), None);
assert_eq!(cache.insert("C", 30), Insertion::Evicted("B", 20));
```

After replacing A, the order is B, A. The search on a miss returns
before editing the deque, so B stays oldest. If insertion still
appends new keys but only successful reads move existing keys, an
update in place would keep order A, B and the next insertion would
evict A with its updated value.

### Interview answers

- **IQ-C048-01.** Two distinct keys may have the same hash. Equality
  is checked separately. The required implication goes from equal
  keys to equal hash results.
- **IQ-C048-02.** Given the occupied fraction, each random query
  index hits an occupied bit with that probability. The joint
  probability multiplies those probabilities, then the result can
  be averaged over possible filter states.
