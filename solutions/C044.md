## Chapter 044

### EX-C044-01 — Predict an unwind outcome

The static string payload matches the boundary's handled type. The
function returns `Err(WorkerPanicked)`, and the score remains 4. The
panic hook can still run before control returns to the caller.

### EX-C044-02 — Predict an abort outcome

An aborting panic terminates the process. The application cannot
observe a return from this function. Destructors that would run only
because the stack was unwound are skipped on an abort.

### EX-C044-03 — Keep effects on one side of the catch

```rust,edition2021
fn update<E>(published: &mut (u16, u16), worker: impl FnOnce() -> Result<(u16, u16), E>)
    -> Result<(), E>
{
    let pair = worker()?;
    *published = pair;
    Ok(())
}

let mut pair = (3, 4);
assert_eq!(update(&mut pair, || Err("unavailable")), Err("unavailable"));
assert_eq!(pair, (3, 4));
assert_eq!(update(&mut pair, || Ok::<_, &str>((5, 6))), Ok(()));
assert_eq!(pair, (5, 6));
```

The worker returns both numbers as one value. The assignment occurs
only on a successful return. An unrelated effect in the worker can
still survive failure.

### EX-C044-04 — Diagnose an unwind-safety failure

The mutable capture can remain observable after an unwind. `&mut T`
does not satisfy the default unwind-safety bound, and the push may
already have changed a caller's vector. Have the closure own a
temporary vector and return it on success. Catch outside that closure
and publish the result afterward. On an unwind the temporary vector
is scoped to the failed worker.

### EX-C044-05 — Choose an unfamiliar payload policy

A panic payload can implement `Drop` and run code when destroyed,
including another panic. A boundary that knows how to drop a particular
payload can map that type to a local outcome. `resume_unwind` transfers
ownership of the unfamiliar payload into an ongoing unwind without
invoking the panic hook again. An enclosing boundary may handle the
payload later.
