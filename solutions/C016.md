## Chapter 016

### EX-C016-01 — Derive the array offset

Reject indices at least 4. Otherwise return
`0x2000 + 4 × index`. For 0 and 3 the results are
`0x2000` and `0x200c`. The last byte is
`0x200f`, three bytes after the last element's
start. Index 4 names the one-past boundary and does
not name an element. Adding the index without
multiplying would measure individual bytes.

### EX-C016-02 — Compare the distance of two raw pointers

```rust,edition2021
let words = [1_u16, 2, 3];
let start = words.as_ptr();
let third = std::ptr::addr_of!(words[2]);
assert_eq!((third as usize) - (start as usize), 4);
```

Both pointers come from the same array, and two elements
of width two give a four-byte separation. The exact
address can change on another run. Award credit for
observing the difference without dereferencing either
raw pointer or assuming an arbitrary absolute location.

### EX-C016-03 — Trace a nested call

| First instant at depth three | Second instant at depth three |
| --- | --- |
| Current: calibrate | Current: read |
| Caller: measure | Caller: measure |
| Outer: main | Outer: main |

Once `calibrate` returns, `measure` is again the
current function. It only then calls `read`. Listing
all four names as simultaneously active would confuse
the full call history with its active suffix.

### EX-C016-04 — Read the Windows x64 leaf

At entry, the first argument is in RCX and the second
in RDX. The cases give RAX values 0, 62, and 0.
`leaq` calculates the sum of register values. It is
not a memory load. The body has no local reservation
instruction. Returning still uses the return address
and the caller follows the ABI. Require the recorded
compiler version, target, optimization level, and
observed assembly for full credit. Do not infer another
target's ABI from these register names.

```rust,edition2021
{{#include ../examples/memory/call_abi.rs}}
assert_eq!(add_words(0, 0), 0);
assert_eq!(add_words(12, 50), 62);
assert_eq!(add_words(u64::MAX, 1), 0);
```

### EX-C016-05 — Avoid overflowing offsets

```rust,edition2021
fn offset(index: usize, len: usize, width: usize) -> Option<usize> {
    if index >= len || width == 0 {
        return None;
    }
    index.checked_mul(width)
}

assert_eq!(offset(2, 3, 4), Some(8));
assert_eq!(offset(3, 3, 4), None);
assert_eq!(offset(0, 3, 0), None);
assert_eq!(offset(usize::MAX - 1, usize::MAX, 2), None);
```

The first check establishes the requested logical domain.
The checked product only returns a value when the finite
type can hold it. Computing with ordinary multiplication
and checking afterward can already panic or wrap. These
premises establish properties of an integer offset, while
a real memory access requires the allocation and pointer
conditions described in the chapter.

### Interview answers for Chapter 016

**IQ-C016-01.** The address identifies a numerical
location in the relevant address space. A valid access
requires the right allocation and permission for the
operation, along with alignment, representation, and
lifetime rules. Equal addresses alone do not establish
the access conditions.

**IQ-C016-02.** Record and compare the source, target,
compiler, and optimization level. Stack usage can change
when code changes, when another ABI applies, or when the
compiler chooses different instructions. The precise claim
comes from observing the other build under its conditions.
