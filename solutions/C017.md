## Chapter 017

### EX-C017-01 — Return an owned measurement

```rust,edition2021
fn boxed_reading() -> Box<u64> {
    let local = Box::new(17);
    local
}

let owned = boxed_reading();
assert_eq!(*owned, 17);
```

The local binding owns the box before returning it.
Afterwards the caller owns the result. Dropping the
caller-owned box releases its allocation. Assuming
that a local name ending always releases the original
resource misses the transfer at the return.

### EX-C017-02 — Choose storage with a contract

```rust,edition2021
const CAPACITY: u16 = 120;
static MARKER: [u8; 3] = *b"LAB";

fn room_info() -> (u16, &'static [u8; 3]) {
    (CAPACITY, &MARKER)
}

assert_eq!(room_info(), (120, b"LAB"));
```

The capacity is interchangeable with any equal `u16`.
The marker's reference identifies the named static
array and is valid throughout execution. Grade each
definition and the types returned by the interface.

### EX-C017-03 — Trace reverse declaration order

Use one initially zero trace and declare a marker with
digit 3, followed by a marker with digit 4. While both
remain in the inner scope, reading the trace gives 0.
Leaving that scope drops the second binding first and
the first binding next. The values written are 4 and
43. A predicted 34 treats declaration order as
destruction order. Use `assert_eq!(trace.get(), 43)`
after the closing brace.

### EX-C017-04 — Release a resource on ordinary early return

```rust,edition2021
use std::cell::Cell;

struct Guard<'a>(&'a Cell<u8>);

impl Drop for Guard<'_> {
    fn drop(&mut self) {
        self.0.set(self.0.get() + 1);
    }
}

fn guarded(trace: &Cell<u8>, early: bool) -> u8 {
    let _guard = Guard(trace);
    if early {
        return 1;
    }
    0
}

let trace = Cell::new(0);
assert_eq!(guarded(&trace, true), 1);
assert_eq!(trace.get(), 1);
assert_eq!(guarded(&trace, false), 0);
assert_eq!(trace.get(), 2);
```

Each return ends the guard's scope once. The result
and trace distinguish the selected path from the
cleanup. The test covers those ordinary returns.
It gives no execution evidence about aborts or
externally terminated processes.

### EX-C017-05 — Report a failed finalization

Hold the owner in the writing function. When writing
fails, return that error immediately and allow
best-effort cleanup of the still-owned resource. On
write success, call `finish` and return its error
or an explicit success result. If `finish` consumes
the owner, its implementation is responsible for any
resource it still holds on failure. If it takes a
borrow, responsibility stays with the original owner.
Full credit requires preserving both errors and stating
whether finalization transfers the owner. Reporting success
after a write alone misses failures that can be detected
only during finalization.

### Interview answers for Chapter 017

**IQ-C017-01.** The caller receives a new binding for
the owner. The transfer preserves access to the allocation,
while lexical visibility of the earlier name ends with
the function. A diagram that erases the allocation at
return misses the move.

**IQ-C017-02.** Some persistence operations can fail
after a buffering layer accepted the earlier write.
`Drop::drop` returns unit and cannot return that
status to the caller. A fallible finalization API gives
the caller information that ordinary scope exit lacks.
