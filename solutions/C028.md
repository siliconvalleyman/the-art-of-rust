## Chapter 028

### EX-C028-01 — Preserve a legitimate zero

```rust,edition2021
fn first(input: &[u8]) -> Option<u8> {
    input.first().copied()
}

assert_eq!(first(&[]), None);
assert_eq!(first(&[0]), Some(0));
assert_eq!(first(&[9, 7]), Some(9));
```

The option has a separate case for the empty slice.
Using zero to signal an empty slice would merge that
case with the input `[0]`. Returning the last element
would fail the multi-element test.

### EX-C028-02 — Keep absent and malformed input apart

```rust,edition2021
{{#include ../examples/data-modeling/src/scan.rs}}
assert_eq!(parse_count(None), Ok(None));
assert_eq!(parse_count(Some("")), Err(ScanError::NotDecimal));
assert_eq!(parse_count(Some("000")), Ok(Some(0)));
```

The first input is absent. The empty string is present
but violates the grammar. Three zeros are valid digits
with numerical value zero. Award credit for distinguishing
all three outcomes.

### EX-C028-03 — Derive the decimal conversion invariant

The prefix values are 0 before processing, then 2, 20,
and 203. At each step the old value counts the preceding
decimal digits and multiplying by ten shifts their place
values. Three digits can describe at most 999, below
`u16::MAX`. The field `"256"` survives prefix arithmetic,
but narrowing fails because the largest byte is 255.
Casting to a byte before checking would return zero.

### EX-C028-04 — Test error precedence

```rust,edition2021
{{#include ../examples/data-modeling/src/scan.rs}}
assert_eq!(parse_count(Some("bad!")), Err(ScanError::TooLong));
assert_eq!(parse_count(Some("x1")), Err(ScanError::NotDecimal));
```

The first string has four bytes and nondigits. Its length
failure takes precedence. The second has two bytes so
the syntax check reports its nondigit.

### EX-C028-05 — Propagate only actual errors

```rust,edition2021
{{#include ../examples/data-modeling/src/scan.rs}}
fn sum_fields(left: Option<&str>, right: Option<&str>) -> Result<Option<u16>, ScanError> {
    let first = parse_count(left)?;
    let second = parse_count(right)?;
    match (first, second) {
        (Some(a), Some(b)) => Ok(Some(u16::from(a) + u16::from(b))),
        _ => Ok(None),
    }
}

assert_eq!(sum_fields(Some("0"), Some("255")), Ok(Some(255)));
assert_eq!(sum_fields(None, Some("0")), Ok(None));
assert_eq!(sum_fields(None, Some("x")), Err(ScanError::NotDecimal));
assert_eq!(sum_fields(Some("x"), Some("1000")), Err(ScanError::NotDecimal));
```

The two `?` operations propagate the first error in call
order. Successful absence still allows the second parser
to run. Only two present fields produce a sum. The greatest
sum is 510 and fits the widened result type. Returning
immediately on absence would hide a later malformed input.

### Interview answers for Chapter 028
