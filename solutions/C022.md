## Chapter 022

### EX-C022-01 — Measure without taking ownership

```rust,edition2021
fn count_bytes(text: &str) -> usize {
    text.len()
}

let owned = String::from("é");
assert_eq!(count_bytes(&owned), 2);
assert_eq!(owned, "é");
```

The slice counts UTF-8 bytes, and the test scalar uses
two. The function has a view while `owned` retains the
buffer. A parameter of type `String` would instead move
the owner on this call.

### EX-C022-02 — End one borrow before writing

```rust,edition2021
let mut value = 4;
let view = &value;
assert_eq!(*view, 4);
let write = &mut value;
*write = 8;
assert_eq!(value, 8);
```

The shared reference's last use precedes the mutable
loan. Moving the first assertion after the mutable
borrow extends the required use of `view`, causing
the conflict. Adding `mut` to the name `view` would
permit reassignment of its binding, without changing
the kind of access the reference provides.

### EX-C022-03 — Modify one value through two short calls

```rust,edition2021
fn add(target: &mut u16, amount: u16) {
    *target += amount;
}

fn update(target: &mut u16) {
    add(&mut *target, 2);
    add(&mut *target, 3);
}

let mut value = 10;
update(&mut value);
assert_eq!(value, 15);
```

The calls use successive shorter loans. The first
returns before the second starts. The owner resumes
access after `update` returns. For all inputs under
this arithmetic policy, the initial value must be
at most `u16::MAX - 5`. Borrowing alone says
nothing about overflow.

### EX-C022-04 — Split and check the boundary

Use the chapter's validated `halves` function. For a
length-three slice, a split at 0 gives lengths 0
and 3, while a split at 3 gives lengths 3 and 0.
A split at 4 returns absence. The half-open ranges
partition indices by whether they are less than the
split, including the end cases. Award credit for
checking the split before calling the underlying method
and for accounting for equality in both ranges.

### EX-C022-05 — Update two distinct positions

```rust,edition2021
fn two_positions(
    values: &mut [u8],
    first: usize,
    second: usize,
) -> Option<(&mut u8, &mut u8)> {
    if first == second || first.max(second) >= values.len() {
        return None;
    }
    let split = first.max(second);
    let (left, right) = values.split_at_mut(split);
    if first < second {
        Some((&mut left[first], &mut right[0]))
    } else {
        Some((&mut right[0], &mut left[second]))
    }
}

let mut sample = [1, 2, 3];
let (first, second) = two_positions(&mut sample, 2, 0).unwrap();
*first = 7;
*second = 9;
assert_eq!(sample, [9, 2, 7]);
assert!(two_positions(&mut sample, 1, 1).is_none());
assert!(two_positions(&mut sample, 0, 3).is_none());
```

The larger index equals the start of the right slice.
The smaller is a valid index inside the left slice.
Each returned reference therefore comes from a different
view, and the two return branches restore requested
order. Equal indices would name the same byte. A
helper that always returned the left position first
would fail the reversed-order test.

### Interview answers for Chapter 022

**IQ-C022-01.** The borrow checker can use the
reference's actual uses to determine where the borrow
must remain valid. The binding may stay in lexical
scope after its last use. A new later use can extend
the required borrow again.

**IQ-C022-02.** Two index expressions alone do not
present a disjoint-slice contract. The split method
creates views whose validated index ranges do not
intersect. The caller can rely on that property through
the safe interface.
