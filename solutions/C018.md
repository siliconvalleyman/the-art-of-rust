## Chapter 018

### EX-C018-01 — Round up without overflowing early

```rust,edition2021
fn round_up(offset: usize, alignment: usize) -> Option<usize> {
    if !alignment.is_power_of_two() {
        return None;
    }
    let remainder = offset % alignment;
    if remainder == 0 {
        Some(offset)
    } else {
        offset.checked_add(alignment - remainder)
    }
}

assert_eq!(round_up(0, 4), Some(0));
assert_eq!(round_up(5, 4), Some(8));
assert_eq!(round_up(usize::MAX, 1), Some(usize::MAX));
assert_eq!(round_up(usize::MAX, 2), None);
assert_eq!(round_up(2, 0), None);
assert_eq!(round_up(2, 3), None);
```

In the unaligned case, every smaller increment is too
small to reach the next multiple. A failed checked
addition means that even this first valid candidate
lies outside the type. Allocating or addressing an
object requires additional checks beyond this arithmetic.

### EX-C018-02 — Derive an alternative order

Start flags at 0 and advance two bytes. The tag starts
at 2 and uses one. Round the next offset, 3, up to 4
for count. That field ends at 8, already a multiple
of the largest alignment. There is one padding byte at
offset 3 and no tail padding. Grade each rounded offset
and the final total. Putting count at offset 3 would
violate the alignment premise.

### EX-C018-03 — Compare native and wire size

Five native records use `5 × 12 = 60` bytes. The
wire encoding occupies `5 × 7 = 35` bytes. The
difference is 25. For a count in a fixed-width type,
use `checked_mul` with the requested stride and report
failure if either requested total overflows. The native
stride includes padding. Adding only field sizes would
incorrectly predict that the two storage totals match.

### EX-C018-04 — Decode a little-endian count field

```rust,edition2021
fn count_field(bytes: &[u8]) -> Option<u32> {
    let field: [u8; 4] = bytes.try_into().ok()?;
    Some(u32::from_le_bytes(field))
}

assert_eq!(count_field(&[1, 2, 3, 4]), Some(0x04030201));
assert_eq!(count_field(&[0, 0, 0, 0]), Some(0));
assert_eq!(count_field(&[1, 2, 3]), None);
```

In a little-endian field the first byte has weight 1.
The last byte has weight `256^3`. Reversing that
convention gives `0x01020304` for the nonsymmetric
test. All-zero bytes alone cannot distinguish the orders.

### EX-C018-05 — Reject unknown flags

After `decode`, require `flags & !0x0003_u16 == 0`.
The complement selects every forbidden bit within 16
bits. If its intersection with flags is empty, all set
bits are permitted. The decoded flags 3 pass, and 4
fails. A short record fails the length check before
checking flags. Examining only one byte of the flag field
leaves possible forbidden bits in the other byte unchecked.

### Interview answers for Chapter 018

**IQ-C018-01.** The next field may need a higher aligned
offset, and a record's tail can be rounded further so
that consecutive array elements remain aligned. These
bytes contribute to size without being additional fields.

**IQ-C018-02.** The representation uses target layout
rules and can contain padding. A file format requires the
same byte order, lengths, and field meaning for all
participants. Encoding explicitly provides those rules.
