## Chapter 001

### EX-C001-01 — Print in reverse

```text
0 READ
1 STORE 0
2 READ
3 WRITE
4 LOAD 0
5 WRITE
6 HALT
```

With `[6, 9, 42]`, rows 0–2 make `A` take 6, 6, and 9,
and cell 0 hold 6 after row 1. Row 3 writes 9. Row 4 sets `A`
to 6 and row 5 writes 6. In general, the first input is in cell 0
when the second replaces `A`. Output changes only at rows 3 and
5, so the missing second input fails before writing. Repeated
`READ` in place of `LOAD` would consume a third byte and lose
the saved value. Award credit for both the preservation argument
and the failure case. The program uses one data cell and seven
fetched instructions on success.

### EX-C001-02 — Count the copies

```text
0 READ
1 WRITE
2 WRITE
3 WRITE
4 HALT
```

After row 0, the input position is 1 and `A` is the first input
byte. The three writes copy `A` without changing it or the input
position. With first byte 7 the output is consequently three 7s.
The program fails at row 0 for empty input. A `READ` before each
write would advance the input position, violating the one-byte
consumption requirement. The complete trace uses five steps on
success and zero data cells.

### EX-C001-03 — Choose a path with the input

```text
0 READ
1 JUMP_IF_ZERO 8
2 READ
3 STORE 0
4 ADD 0
5 WRITE
6 LOAD 1
7 JUMP_IF_ZERO 10
8 READ
9 WRITE
10 HALT
```

A zero flag takes rows 0, 1, 8, 9, 10 and writes the data. A
nonzero flag takes rows 0–7 and row 10. Rows 2–4 derive the
doubled byte, and cells 0 and 1 remain independent. The read
of cell 1 takes place after output and causes row 7 to skip rows
8–9. At 128 the nonzero path wraps to 0. Either path reaches
its data read before the first write. Award credit for exactly
one write and one read of the data on every successful path.
Branching after reading both bytes without saving the flag tests
the data and can choose the wrong path.

### EX-C001-04 — Expand the test domain

```text
0 READ
1 STORE 0
2 READ
3 ADD 0
4 WRITE
5 READ
6 STORE 0
7 READ
8 ADD 0
9 WRITE
10 HALT
```

Rows 0–4 output the first sum. Rows 5–6 replace the first pair's
saved byte before row 8 can use cell 0 again. Thus the second add
uses the second pair's two bytes. For `[10, 21, 0]`, the program
writes 31 at row 4, stores 0 at row 6, and fails at row 7.
Reporting an error does not erase 31 from the output stream.
Award credit for identifying the overwrite at row 6 and the
precise partial result. Simply adding the next pair to the sum
already in `A` would use an earlier value and change the contract.

### EX-C001-05 — Bound a looping machine

**Pseudocode.** A step returns one of continue, halt, or an execution
error. Its fetch and operand validation happen only if called.

```text
initialize machine state
remaining = budget
while remaining is positive:
    subtract 1 from remaining
    outcome = execute one step
    if outcome is halt or an execution error:
        return outcome and the output so far
return budget error and the output so far
```

At the start of each iteration, the number of attempted steps plus
the remaining budget equals the original budget. Initially no attempts
have occurred. The decrement and next attempt preserve the sum,
and the nonnegative remaining budget strictly decreases. A row 0
self-jump with an initial register of 0 returns the budget error
after consuming all available steps. A first-row halt succeeds with
budget 1 and returns the budget error with budget 0. Award credit
for counting the halt and keeping previously written bytes. A
budget test after the step admits one extra step when the budget is
zero. See the reference runner in the foundations crate for tests of
both outcomes and a partial-output case.

### Interview answers for Chapter 001

**IQ-C001-01.** If the row is `ADD 0`, the runs can have different
values in cell 0. If the row is `READ`, the input sequence or
position can differ. Specify the row and explain the state on which
it depends. Giving a different `PC` contradicts the premise.

**IQ-C001-02.** For 250 and 20, wrapped addition yields 14, but the
ordinary count is 270. Revisit the maximum supported sum and how
it is represented. Blaming the add for following its stated rule
confuses a representation choice with an incorrectly executed step.
