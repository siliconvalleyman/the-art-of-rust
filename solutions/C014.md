## Chapter 014

### EX-C014-01 — Destructure one reading

```rust,edition2021
let reading = (42_u16, true);
let (count, ready) = reading;
assert_eq!(count, 42);
assert!(ready);
```

The positions have different types, `u16` and
`bool`. The tuple type records both. An array of
one element type would require an extra representation
decision for the Boolean and lose that distinction.

### EX-C014-02 — Select a fixed window

```rust,edition2021
let readings = [4_u8, 5, 6, 7];
let window = &readings[1..3];
assert_eq!(window, &[5, 6]);
assert_eq!(window.len(), 2);
assert_eq!(window.get(2), None);
```

The upper endpoint 3 excludes array position 3, holding 7.
The view has its own indices 0 and 1. Treating the endpoint
as included would produce three elements.

### EX-C014-03 — Count representation units

```rust,edition2021
let decomposed = "e\u{301}";
let composed = "é";
assert_eq!(decomposed.len(), 3);
assert_eq!(decomposed.chars().count(), 2);
assert_eq!(composed.len(), 2);
assert_eq!(composed.chars().count(), 1);
assert_ne!(decomposed, composed);
```

The decomposed form contains a one-byte ASCII letter and
a two-byte combining accent. The composed form contains
one two-byte scalar. Equality on the strings in this
example compares their contents without normalization.
Counting what appears visually cannot determine these
byte or scalar lengths.

### EX-C014-04 — Validate a byte sequence before using it

```rust,edition2021
fn validated_text(bytes: &[u8]) -> Option<&str> {
    std::str::from_utf8(bytes).ok()
}

assert_eq!(validated_text(&[]), Some(""));
assert_eq!(validated_text(&[0xc3, 0xa9]), Some("é"));
assert_eq!(validated_text(&[0xc3]), None);
```

The function returns a view of the supplied bytes after
validating them. A single leading byte `0xc3` requires
a continuation byte, so the truncated input fails. The
empty byte string is valid text. Lossy conversion would
choose replacement text for the invalid sequence.

### EX-C014-05 — Preserve UTF-8 under a byte budget

Start from the bounded byte index and move left while it
lies inside an encoding. Every skipped position is therefore
invalid as a boundary. On reaching the first valid index,
the returned prefix is the longest one satisfying both
conditions. Valid UTF-8 uses one to four bytes per scalar,
so at most three decrements reach a boundary. For limits
0, 2, 4, 6, 7, and 8, the expected prefixes are
`""`, `"A"`, `"Aé"`, `"Aé"`, `"Aé🦀"`,
and `"Aé🦀"`. The chapter's executable function implements
this reasoning. Slicing directly at the numerical limit
would fail at 2, 4, or 6.

### Interview answers for Chapter 014

**IQ-C014-01.** UTF-8 encodes different scalar values in
one through four bytes. `"Aé🦀"` has widths 1, 2, and 4.
The string's byte length counts all seven, while scalar
iteration reports three values.

**IQ-C014-02.** Yes. A base letter and following
combining accent can be separate scalar values in one
grapheme cluster. A cut immediately before the accent
preserves valid UTF-8 and still separates that user-visible
unit. Use a requirement expressed in grapheme boundaries
when that is the intended segmentation.
