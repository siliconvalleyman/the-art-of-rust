## Chapter 015

### EX-C015-01 — Handle the threshold exactly

```rust,edition2021
fn label(size: u16, limit: u16) -> &'static str {
    if size > limit { "inspect" } else { "regular" }
}

assert_eq!(label(9, 10), "regular");
assert_eq!(label(10, 10), "regular");
assert_eq!(label(11, 10), "inspect");
```

Equality selects the second block. Choosing `>=`
would classify the equality case as oversized.

### EX-C015-02 — Count all qualifying sizes

```rust,edition2021
fn oversized_count(sizes: &[u16], limit: u16) -> usize {
    let mut count = 0;
    for &size in sizes {
        if size > limit {
            count += 1;
        }
    }
    count
}

assert_eq!(oversized_count(&[4, 12, 10, 15], 10), 2);
assert_eq!(oversized_count(&[], 10), 0);
assert_eq!(oversized_count(&[10, 10], 10), 0);
assert_eq!(oversized_count(&[12, 12], 10), 2);
```

The count equals the number of qualifying elements in
the processed prefix. At the beginning both counts
are zero. Every iteration changes both counts by one
exactly when the current element qualifies. The count
cannot exceed the slice's length, which is representable
as `usize`. A Boolean flag would lose the number of
matches.

### EX-C015-03 — Report the first crossing

Use the chapter's enumerating function. A forward
scan can return index 0 as soon as it compares 12 to
10. A reverse scan sees index 2 first. If it starts
in reverse order, it has to ensure that no smaller
matching position exists before choosing the final
answer. Credit requires checking the returned position
and explaining why merely detecting some match is
insufficient.

### EX-C015-04 — Guard a remainder

```rust,edition2021
fn divides(total: u16, divisor: u16) -> bool {
    divisor != 0 && total % divisor == 0
}

assert!(!divides(10, 0));
assert!(divides(10, 5));
assert!(!divides(10, 3));
assert!(divides(0, 5));
```

When the divisor is zero, the left condition is false
and Rust skips the remainder. Otherwise the operation
is defined for these unsigned inputs. Using bitwise
AND on the two logical results would evaluate both
operands and could trigger division by zero.

### EX-C015-05 — Compare recursive and iterative checks

```rust,edition2021
fn all_fit(sizes: &[u16], limit: u16) -> bool {
    for &size in sizes {
        if size > limit {
            return false;
        }
    }
    true
}

assert!(all_fit(&[], 10));
assert!(!all_fit(&[1, 15, 2], 10));
assert!(all_fit(&[1, 10, 2], 10));
```

Before every comparison, all previously processed
elements fit. That holds for the empty prefix and
remains true for a comparison that continues. Returning
false gives a witness to failure. Finishing the finite
scan means every element was processed and fit. Both
forms can return immediately on a failure, and both
use at most `n` comparisons. The iteration uses
constant auxiliary space. Recursion can have linear
depth when every value fits.

### Interview answers for Chapter 015

**IQ-C015-01.** `return` ends the function and supplies
its result. A plain `break` ends the enclosing loop
and execution may continue later in the same function.
Using the wrong exit can skip required work or continue
when a result has already been determined.

**IQ-C015-02.** The proof establishes that the call chain
has finite depth. The amount of stack available on a
particular machine is also finite. A long valid input
can require more active calls than fit on that stack.
