## Chapter 033

### EX-C033-01 — Extend an existing type locally

```rust,edition2021
trait EmptyInput {
    fn empty_input(&self) -> bool;
}

impl EmptyInput for [u8] {
    fn empty_input(&self) -> bool { self.is_empty() }
}

assert!(b"".as_slice().empty_input());
assert!(![7_u8].as_slice().empty_input());
```

The trait is local. It can be implemented for the
slice type even though the slice type is not defined
here. Neither assertion changes the behavior of
the slice's existing methods.

### EX-C033-02 — Format a local wrapper

```rust,edition2021
use std::fmt::{self, Display, Formatter};
struct Bay(u8);

impl Display for Bay {
    fn fmt(&self, out: &mut Formatter<'_>) -> fmt::Result {
        write!(out, "bay-{}", self.0)
    }
}

assert_eq!(Bay(3).to_string(), "bay-3");
assert_eq!(3_u8.to_string(), "3");
```

The wrapper defines a distinct local type. An alias
would keep the type identity of `u8`, and attempting
to implement the standard trait for it would not create
a separate implementation.

### EX-C033-03 — Exhibit an overlapping type

The type `u8` implements Debug and thus satisfies
the blanket bound. The specific declaration would
apply to that same type, giving one witness. Use a
local-specific wrapper with a design that avoids the
overlap, or create a separate trait for the different
operation. Declaring the concrete rule later does
not change what the blanket covers.

### EX-C033-04 — Implement a blanket rule

```rust,edition2021
use std::fmt::Display;
trait Bracketed {
    fn bracketed(&self) -> String;
}

impl<T: Display> Bracketed for T {
    fn bracketed(&self) -> String { format!("[{self}]") }
}

assert_eq!(7_u8.bracketed(), "[7]");
assert_eq!("cargo".bracketed(), "[cargo]");
```

Both types satisfy Display and the default Sized
bound on the type parameter. The method can rely
on Display formatting for every type it covers.

### EX-C033-05 — Separate competing policies

```rust,edition2021
use std::fmt::{self, Display, Formatter};
struct Customer(u32);
struct Log(u32);

impl Display for Customer {
    fn fmt(&self, out: &mut Formatter<'_>) -> fmt::Result {
        write!(out, "Parcel {}", self.0)
    }
}
impl Display for Log {
    fn fmt(&self, out: &mut Formatter<'_>) -> fmt::Result {
        write!(out, "parcel_id={}", self.0)
    }
}

assert_eq!(Customer(11).to_string(), "Parcel 11");
assert_eq!(Log(11).to_string(), "parcel_id=11");
```

The selected wrapper encodes the policy. A single
Display implementation for one type can choose based
on its data and formatting flags, but two different
implementations for that same type would conflict.

### Interview answers for Chapter 033

**IQ-C033-01.** An orphan implementation is outside the
crate's permitted ownership boundary. Overlap means two
implementations can apply to the same trait and type.

**IQ-C033-02.** Determine all types its bound can cover
and which current or planned implementations share those
types. Give a concrete witness when two rules intersect.
