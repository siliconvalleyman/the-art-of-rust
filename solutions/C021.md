## Chapter 021

### EX-C021-01 — Transfer one owner

```rust,edition2021
fn relay() -> String {
    let staged = String::from("ready");
    let queued = staged;
    queued
}

let owner = relay();
assert_eq!(owner, "ready");
```

Ownership passes from `staged` to `queued` to the
caller. The original text is available through the last
binding. Award credit for a trace with one owner at each
point and the executed assertion. Preserving all names
as independently usable would require a different transfer.

### EX-C021-02 — Repair use after move

Replace the later `staged` use with `queued` if
only the transferred value is needed. Alternatively set
`let queued = staged.clone();` before using both
strings. The latter requests a second independently owned
buffer for this nonempty text. Moving an owned local
already makes its old name unavailable. Adding `mut`
without assigning a new value cannot make the moved-out
value readable.

### EX-C021-03 — Distinguish Copy from Clone

```rust,edition2021
let original = 77_u32;
let copy = original;
assert_eq!((original, copy), (77, 77));

let mut current = String::from("open");
let snapshot = current.clone();
current.push('!');
assert_eq!(current, "open!");
assert_eq!(snapshot, "open");
```

The integer is Copy and the by-value use leaves it
initialized. The string operation invokes the library's
Clone implementation, which copies the stored text.
The independent edit is the evidence that the second
string's contents were preserved.

### EX-C021-04 — Track a partially moved tuple

```rust,edition2021
let mut entry = (String::from("room"), String::from("open"));
let old_label = entry.0;
assert_eq!(entry.1, "open");
entry.0 = String::from("hall");
assert_eq!(entry, (String::from("hall"), String::from("open")));
assert_eq!(old_label, "room");
```

`old_label` owns the moved string. The tuple owns
the second field throughout, then receives a new first
field. Until that assignment, the tuple cannot supply
both fields as an initialized aggregate. Award credit
for naming the owner of each of the three remaining
strings, even though two are held inside one tuple.

### EX-C021-05 — Observe exactly one cleanup after transfer

```rust,edition2021
use std::cell::Cell;

struct Guard<'a>(&'a Cell<u8>);

impl Drop for Guard<'_> {
    fn drop(&mut self) {
        self.0.set(self.0.get() + 1);
    }
}

fn transfer(guard: Guard<'_>) -> Guard<'_> {
    guard
}

let count = Cell::new(0);
let first = Guard(&count);
let last = transfer(first);
assert_eq!(count.get(), 0);
drop(last);
assert_eq!(count.get(), 1);
```

The destructor does not execute at either move. The
last owner is explicitly destroyed and cleanup runs
once on this path. The test does not exercise an
aborting or externally killed process. Measuring only
the final count could miss incorrectly performing
cleanup before the transfer completed.

### Interview answers for Chapter 021

**IQ-C021-01.** Scope controls the location where the
name is visible. Moving a non-Copy value takes its
contents out of the source place, so the binding's
visibility alone cannot supply an initialized value.

**IQ-C021-02.** Read the target type's Clone contract.
A String clone owns independent contents. A shared
ownership handle can clone the handle while retaining
one shared resource. Cloning the value named by the
handle and cloning the handle itself need not have
the same ownership or cost.
