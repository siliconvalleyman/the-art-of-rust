## Chapter 042

### EX-C042-01 — Trace the first failure

`" 10 "` reads, trims, and parses to `Ok(10)`. Empty text reads
successfully, then parsing yields `Err(Parse(...))`. The byte `0xff`
fails UTF-8 validation in `read_to_string`, producing `Err(Read(...))`
without calling the parser.

### EX-C042-02 — Propagate an optional field

```rust,edition2021
fn first_nonzero(input: Option<u16>) -> Option<u16> {
    let value = input?;
    (value != 0).then_some(value)
}

assert_eq!(first_nonzero(None), None);
assert_eq!(first_nonzero(Some(0)), None);
assert_eq!(first_nonzero(Some(8)), Some(8));
```

Absence exits at `?`. A present value reaches the Boolean condition.

### EX-C042-03 — Choose context at a conversion site

```rust,edition2021
use std::{fs::File, io::{self, Write}, path::Path};

enum HeaderError {
    Create(io::Error),
    Write(io::Error),
}

fn create_header(path: &Path) -> Result<(), HeaderError> {
    let mut file = File::options().write(true).create_new(true).open(path)
        .map_err(HeaderError::Create)?;
    file.write_all(b"count\n").map_err(HeaderError::Write)?;
    Ok(())
}
```

Both variants preserve an I/O error. The call sites supply the
distinction. A successful creation can leave an artifact if the
subsequent write fails, and this code performs no rollback.

### EX-C042-04 — Measure effects before early return

```rust,edition2021
use std::num::ParseIntError;

fn read_pair(first: &str, second: &str, second_attempts: &mut u8)
    -> Result<(u16, u16), ParseIntError>
{
    let first = first.parse()?;
    *second_attempts = second_attempts.saturating_add(1);
    let second = second.parse()?;
    Ok((first, second))
}

let mut count = 0;
assert!(read_pair("x", "2", &mut count).is_err());
assert_eq!(count, 0);
assert!(read_pair("1", "x", &mut count).is_err());
assert_eq!(count, 1);
assert_eq!(read_pair("1", "2", &mut count).unwrap(), (1, 2));
```

The second attempt is recorded even when its parser returns an error.
Saturating addition keeps the instrumentation defined at the counter limit.

### EX-C042-05 — Design a bounded read contract

Choose `B` so that `B + 1` can be represented as both the reader's
`u64` limit and the byte buffer's `usize` length. Use `input.take(B + 1)`
with `Read::read_to_end` into a byte buffer. Check the resulting length
before decoding UTF-8 or parsing. If the read succeeds with `B + 1`
bytes, the source exceeded the limit. With `B` bytes, the adapter still
had room, so a conforming finite source signaled end of input. A read
error can still interrupt either case. At the exact limit an open stream
can stall while the reader waits for another byte or end of input.
A deadline or timeout requires another mechanism at the I/O boundary.
