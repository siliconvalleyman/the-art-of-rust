## Chapter 006

### EX-C006-01 — Separate safety from completeness

Let `P(n)` mean `n ≤ 10` and let `Q(n)` mean
`n ≤ 10 AND remainder(n, 2) = 0` over bytes. The filter
satisfies `Q ⇒ P` by the first part of the conjunction.
It violates `P ⇒ Q` for input 1. Write the desired
predicate as the conjunction defining `Q`. It accepts
0 and 10 and rejects 11. Replacing “AND” by “OR” would
accept 12 and odd values below 10. Credit requires identifying
which implication fails, then rejecting an odd byte within
the original limit.

### EX-C006-02 — Guard a configurable limit

If `b > limit`, fail immediately. With `a ≥ 0`, adding
it to `b` cannot lower the sum. Otherwise subtract
`b` from `limit` and fail if `a` exceeds the result.
The subtraction is now within the byte domain. In that
path `a ≤ limit − b` is equivalent to `a + b ≤ limit`
by adding or subtracting the same value on each side.
On success the sum fits because the limit fits. The specified
cases give 5, failure on the first guard, and failure on
the second guard. Subtracting before the first guard might
underflow. The function takes constant time and space in the
fixed-width model.

### EX-C006-03 — Search for a witness

```text
for each index i in order:
    if totals[i] > limit: return that index
return absent
```

At the start of each iteration every preceding value is at
most the limit. This holds for the empty prefix and is
maintained because an over-limit value would cause an
immediate return. Finding a violation returns the first index
by the invariant. On exhaustion, absence establishes
“for every valid index, its total is at most the limit.”
For a list of length `n`, work is at most `n` comparisons
and the implementation uses one traversal position. Empty
input returns absence, and `[6, 6]` at limit 5 returns
index 0. Returning the last index would violate the first
occurrence requirement.

### EX-C006-04 — Check a shared calibration input

For each row test every column, stopping that row at its
first failure. Return true at the first row with no failing
column. Otherwise return false after visiting all rows.
This computes `∃ input, ∀ monitor, passes(input, monitor)`.
With no rows there is no witnessing input. With no columns
each existing row satisfies its universal condition, so a
nonempty set of rows yields true. Figure 1 yields false.
Adding a row `[pass, pass]` yields true. Validating that
each row has the declared width before searching for a
witness rejects irregular tables even when an early row
would otherwise pass. The alternate order lets different
rows witness different monitors. Award credit for recognizing
both empty domains and distinguishing the two orders.

### EX-C006-05 — Negate a guarded claim

The negation is “some record is accepted and its timestamp
does not match.” Walk the stream in order. At each record
return its index if both conditions hold, and continue
otherwise. At the start of each step there is no witness in
the processed prefix. On exhaustion the original claim holds
for this stream. A rejected record with a bad timestamp
leaves the predicate false, while an accepted record with a
bad timestamp supplies the witness. Using a disjunction can
return an accepted record even when its timestamp matches.

### Interview answers for Chapter 006

**IQ-C006-01.** For every input, acceptance implies validity.
With no acceptance, every instance is vacuous. Require each
valid input to be accepted, or specify a weaker useful
acceptance property if that is the design. A counterexample
is any valid input refused by the always-reject implementation
when validity is sufficient for acceptance.

**IQ-C006-02.** In a two-by-two matrix with only the diagonal
true, each column has a true cell, but no row has all cells
true. State which axis is the monitor and which is the input.
Choosing a different input in each column satisfies a different
requirement from choosing one row for all columns.
