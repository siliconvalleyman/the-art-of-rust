## Chapter 034

### EX-C034-01 — Compare two call paths

```rust,edition2021
{{#include ../examples/abstractions/src/dispatch.rs}}
let adjustment = Offset(4);
let object: &dyn Adjust = &adjustment;
assert_eq!(via_generic(&adjustment, 8), 12);
assert_eq!(via_object(object, 8), 12);
```

Both calls use a shared view of the same concrete
value. Converting the borrow to the trait-object view
adds the metadata needed for dispatch. The program
need not allocate to obtain that view.

### EX-C034-02 — Prove that adjustment order matters

```rust,edition2021
{{#include ../examples/abstractions/src/dispatch.rs}}
assert_eq!(pipeline(&[&Offset(2), &Scale(4)], 5), 28);
assert_eq!(pipeline(&[&Scale(4), &Offset(2)], 5), 22);
```

The first path computes `(5 + 2) × 4`. The second
computes `5 × 4 + 2`. Their intermediate states and
results differ. Feeding 28 to the second path would
test a different input and would not isolate order.

### EX-C034-03 — Classify an operation that returns Self

```rust,edition2021
trait Duplicate {
    fn duplicate(&self) -> Self where Self: Sized;
    fn value(&self) -> u8;
}

struct Entry(u8);
impl Duplicate for Entry {
    fn duplicate(&self) -> Self { Self(self.0) }
    fn value(&self) -> u8 { self.0 }
}

let entry = Entry(9);
let view: &dyn Duplicate = &entry;
assert_eq!(view.value(), 9);
assert_eq!(entry.duplicate().value(), 9);
```

The concrete call returns an Entry. Object callers
can use the shared value method. The Sized
restriction excludes the duplication method from
object dispatch, making the remaining interface
usable through the trait object.

### EX-C034-04 — Compose a mixed list without cloning

```rust,edition2021
{{#include ../examples/abstractions/src/dispatch.rs}}
let offset = Offset(2);
let scale = Scale(3);
assert_eq!(pipeline(&[&offset, &scale, &offset], 4), 20);
```

The intermediate states are 6, 18, and 20. Both
uses of the offset borrow the same value, compatible
because the trait method takes a shared reference.
Borrowing these instances keeps their ownership with
the local variables.

### EX-C034-05 — Compare what a build can establish

Assembly for a documented build can reveal whether
one call site uses an indirect branch or a resolved
implementation. Throughput also depends on data and
the CPU's handling of the selected instructions.
Hold Rust version, target, and optimization settings
constant. Use equal ordered arithmetic work, first
with one implementation and then with a stable
mixed sequence. Report sizes and runs separately
from assumptions about branch prediction or inlining.

### Interview answers for Chapter 034

**IQ-C034-01.** The trait object here is a borrowed
view. Its data reference can point to a value that
is already live, as with other borrowing. The
lifetime keeps it from outlasting that data.

**IQ-C034-02.** If the compiler knows which concrete
implementation a call will select, it can emit a direct
call or its inlined effect while preserving observable
behavior. Other builds may retain the indirect call.
