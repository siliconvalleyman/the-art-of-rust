## Chapter 030

### EX-C030-01 — Recover and retry

```rust,edition2021
{{#include ../examples/data-modeling/src/dispatch.rs}}
let draft = Dispatch::new(17);
let (draft, error) = draft.prepare(0).unwrap_err();
assert_eq!(error, PrepareError::Empty);
assert_eq!(draft.id(), 17);
let ready = draft.prepare(1).unwrap();
assert_eq!(ready.id(), 17);
```

The receiver is moved into the method. Returning it on
failure supplies a value to retry. An error without the
draft would require the caller to create another one or
obtain its state elsewhere.

### EX-C030-02 — Test an inclusive bound

```rust,edition2021
{{#include ../examples/data-modeling/src/dispatch.rs}}
let ready = Dispatch::new(17).prepare(500).unwrap();
let tracking = NonZeroU64::new(99).unwrap();
assert_eq!(ready.record_shipment(tracking).receipt(), (17, 500, tracking));
let (draft, error) = Dispatch::new(17).prepare(501).unwrap_err();
assert_eq!(draft.id(), 17);
assert_eq!(error, PrepareError::TooMany);
assert_eq!(draft.prepare(0).unwrap_err().1, PrepareError::Empty);
```

The upper endpoint is part of the Ready domain.
501 leaves the draft unchanged. A lone `parcels <= 500`
condition would admit zero and violate the lower bound.

### EX-C030-03 — Prove that an operation is unavailable

Use `draft.prepare(5).unwrap()` to obtain the Ready
value, then invoke `ready.record_shipment(tracking)`.
With identifier 17 and tracking number 99, the receipt
is identifier 17, five parcels, and number 99. The
compiler reports E0599 on the direct draft call.
A helper using one common state representation would
need to dispatch on runtime state before attempting
the effect.

### EX-C030-04 — Store mixed states

```rust,edition2021
{{#include ../examples/data-modeling/src/dispatch.rs}}
enum Entry {
    Draft(Dispatch<Draft>),
    Shipped(Dispatch<Shipped>),
}

fn id(entry: &Entry) -> u32 {
    match entry {
        Entry::Draft(dispatch) => dispatch.id(),
        Entry::Shipped(dispatch) => dispatch.id(),
    }
}

let shipped = Dispatch::new(18).prepare(1).unwrap()
    .record_shipment(NonZeroU64::new(9).unwrap());
let entries = [Entry::Draft(Dispatch::new(17)), Entry::Shipped(shipped)];
assert_eq!([id(&entries[0]), id(&entries[1])], [17, 18]);
```

Both variants own values of different concrete types.
Borrowing the enum borrows its payload. Each case
calls the shared identifier method and neither moves
its entry.

### EX-C030-05 — Separate state from an external effect

A ready dispatch can obtain a confirmed acceptance,
a confirmed rejection, or a result that is still
unknown. Return a receipt only after positive evidence
such as an authoritative acknowledgment or a later
status query. A timeout is compatible both with no
acceptance and with a reply lost after acceptance. The
unknown state should retain its request identity so the
caller can reconcile it. Award credit for preserving
uncertainty rather than manufacturing a rejection.

### Interview answers for Chapter 030

**IQ-C030-01.** The compiler looks for the method on
the concrete type. The method exists only on the ready
instantiation, so the call cannot reach a runtime check
on a draft.

**IQ-C030-02.** The caller receives the capability
to retry on a draft after failure. The private
implementation and tests establish whether that returned
draft still represents the same identifier and state.
