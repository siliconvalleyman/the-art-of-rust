### EX-C002-01 — Fill bits from least to most significant

**Beginner.** Convert an unsigned byte to an array of exactly eight
0s and 1s, most significant bit first. Write the division procedure
as pseudocode. For 37 expect `00100101`, for 0 expect eight zeros,
and for 255 expect eight ones. Explain which output position you
fill first and why. Use a fixed array rather than a decimal number
whose digits happen to be zero and one.

### EX-C002-02 — Decode a two-digit label

**Intermediate.** Define a decoder for exactly two ASCII hex digits
in either case, with an error otherwise. Given `aF`, return 175.
Check `00`, `FF`, an empty field, `0x`, a trailing space,
and `Ａ0` (a fullwidth letter). Provide pseudocode and justify
why the value fits a byte. Hint: each character must first produce
a value in 0 through 15.

### EX-C002-03 — Keep the carry

**Intermediate.** Derive byte addition that returns a low byte and
carry without performing a native addition of the whole inputs.
Give the column rule, prove the prefix invariant, and trace 255 and
1. Compare against a reference that can represent 510. Include 0
plus 0, 255 plus 0, and 255 plus 255. Full credit requires the
exit argument and an explanation of why the temporary column sum
fits.

### EX-C002-04 — Decode two bytes in a declared order

**Beginner.** Write a function that consumes exactly two bytes and a
choice of byte order. For `[0x12, 0x34]`, return `0x1234` in
big-endian mode and `0x3412` in little-endian mode. Return an error
for any length other than two. Use multiplication or shifting on
the widened high component. Explain your test for a swapped order.

### EX-C002-05 — Choose a count overflow contract

**Intermediate.** Implement a policy that rejects an addition of
two unsigned byte counts when their sum is above 255. Produce 255
for 250 and 5, and an error for 250 and 6. Use the carry in
EX-C002-03, and explain when checking the wrapped result alone
would be insufficient. Test cases must distinguish rejection from a
valid result of zero.
