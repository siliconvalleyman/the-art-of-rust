### EX-C025-01 — Test a zero-capacity pool

**Beginner.** Set a permit pool's capacity to zero,
try twice to acquire a lease, and verify that the
free count stays zero. Explain why a failing operation
cannot create an owner.

### EX-C025-02 — Transfer a guard unchanged

**Intermediate.** Acquire a lease for a pool of
capacity one. Pass it through a function that returns
it to the caller. Verify that the free count remains
zero until the returned guard is dropped, then
becomes one.

### EX-C025-03 — Restore a permit on early failure

**Intermediate.** Write a function that returns an
error for invalid input after acquiring a lease.
Give distinct errors for no available permit and
invalid input. Test that invalid input restores a
permit and that lack of capacity takes precedence.

### EX-C025-04 — Predict forgotten cleanup

**Challenge.** In the simulated pool, consume a
capacity-one lease with `std::mem::forget`. State and
verify the next acquisition result. Explain why the
accounting proof still holds with an outstanding
permit and why this is a resource leak.

### EX-C025-05 — Return a finalization error

**Challenge.** Design an operation that starts with
an acquired owner, writes a record, and explicitly
finalizes a sink. Name outcomes for success, write
failure, and finalization failure. Write a test
strategy that verifies which error is returned and
when ordinary cleanup is attempted.

### Knowledge check

- **IQ-C025-01, beginner.** Why should a guard be
  created only after acquisition succeeds?
- **IQ-C025-02, intermediate.** Why can an unsafe
  abstraction usually not rely on every guard's
  destructor executing?
